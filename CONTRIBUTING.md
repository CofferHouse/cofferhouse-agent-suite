# Contributing

CofferHouse Scout is currently defining its first MVP. Contributions that improve clarity, safety, reproducibility or Arc compatibility are welcome.

## Before opening a pull request

1. Open an issue describing the problem or proposed change.
2. Keep the change focused and explain its security implications.
3. Add or update tests when code is introduced.
4. Do not include secrets, private keys or production credentials.
5. Do not describe experimental functionality as live or audited.

## Good first contributions

- documentation corrections;
- Arc integration research;
- market-schema proposals;
- risk-factor references;
- test fixtures;
- accessibility improvements;
- threat-model feedback.

By contributing, you confirm that you have the right to submit the work. A formal source-code license will be selected before outside code contributions are accepted.
